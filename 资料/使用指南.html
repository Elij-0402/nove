网文工坊 · 使用指南

把「对标爆款 → 拆解蒸馏 → 写出超越原作的新作」固化成一条可反复使用的 skill 链。任何时候不确定从哪开始、想知道某部写到哪、要接着往下推，都先敲 /novel。

1总览

网文工坊是一套中文网文写作流水线。它把写作拆成 拆书 → 立项 → 设定 → 大纲 → 写章 → 审稿 几个阶段顺次推进，用 7 个 skill 各管一段，用一份状态机把「下一步该干什么」写死，让你可以反复跑、随时接续。

其中 立项、总纲、每卷卷纲、每一章 是人工关卡：流水线跑到这里会停下、等你拍板；其余阶段由总控自动接续，不用你逐个点。

一条贯穿全链的铁律：借功能，不借形态。对标作品的具体装置、桥段、人物关系结构一律重新设计，能借的只是功能与数据（节奏、配比这类）。这条从拆书（只写抽象层、不抄情节）、立项（差异清单逐项标「借/改」）一直贯到设定（人名不与对标重名同音）和大纲（原创性自检）。

目录地图

整个工作区就四个业务目录，产物各归各位：

目录放什么
作品/<书名>/一部作品的全部产物。项目.md 是它唯一的进度真源；下有 设定/ 大纲/ 正文/ 审稿/ 摘要/，外加 立项方案.md、风格档案.md。
对标库/<书名>/对标源本和拆书产物：原文.txt 加拆出来的 拆书报告.md、基线指标.md、风格档案.md 等。
规范/跨作品共用的模板和标准：模板/（设定、大纲）、读者画像/（番茄、起点、晋江）、AI腔清单.md。
资料/立项前的调研和这套工坊的 SPEC，不参与流水线。（本指南就在这里。）

2快速上手

不用记流程——任何时候敲 /novel，它会扫一遍作品库、告诉你每部在哪一步、下一步该敲什么。下面是从零到写出第一章的典型路径。

先看你手上有什么（三种起点）

现状下一步
对标库是空的把对标源本放进 对标库/<书名>/原文.txt，再敲 /novel-chaishu 拆书。
对标库里有已拆完的书（三份产物齐全）敲 /novel-lixiang 立项（指定主对标）。
已经有作品在写了敲 /novel 接着往下推。

最短命令序列

  1. /novel-chaishu —— 拆对标书，产出三份拆书产物（在 对标库/ 里）。
  2. /novel-lixiang —— 出 3 个方案 ★ 立项关卡，你选一个 / 让它合并 / 指出改哪。拍板后自动建 作品/<书名>/项目.md，落到「设定 / 待开始」。
  3. /novel 或 /novel-sheding —— 生成设定（无关卡，做完自动推进到总纲）。
  4. /novel-dagang —— 写总纲 ★ 总纲关卡，你拍板；通过后它顺势写第 1 卷卷纲 ★ 卷纲关卡，再拍板。
  5. 此后进入写章循环：写当前章 → 审稿 → ★ 每章关卡 你拍板 → 下一章……一卷写完做卷末结算，再写下一卷卷纲。
进了写章循环后，多数时候你只需反复敲 /novel：它自动写章、审稿，停在每章关卡等你一句「通过」。

3状态机与进度真源

作品/<书名>/项目.md 是一部作品唯一的进度来源。产物文件在不在只用来核对；两边对不上，以项目.md 为准，并把出入报给作者。它的三条维护责任：

① 立项拍板时由 novel-lixiang 创建。② 每个阶段 skill 做完自己那一步，按状态机改「进度」一节。③ 每个关卡拍板后，在「关卡日志」追加一行。

项目.md 模板

# 《书名》

## 基本信息

- 书名：和 作品/ 下的目录名一致
- 题材：细分类型，比如「现代言情 · 破镜重圆」
- 平台：番茄、起点、晋江这类平台名
- 每章目标字数：一个整数，比如 3800
- 目标篇幅：总字数、章数、卷数，比如「约 40 万字，约 100 章，4 卷」
- 主对标：《书名》—— 借：爆点机制、情绪点配比、结构和节奏、钩子手法；基线指标以它为准
- 辅助对标：《书名》—— 借：开局节奏；没有就写「无」

字段规则要点

  • 平台决定审稿用哪份读者画像；每章目标字数是写章和审稿查字数的基准。
  • 主对标的借鉴项取拍板方案差异清单里标「借」的维度。基线指标只认主对标，辅助对标只提供它的借鉴项。
  • 当前卷、当前章写数字，还没到卷纲/写章阶段时写「—」。当前章是全书连续的章序号，和 正文/NNNN-章名.md 编号一致。
  • 停顿频率=每写完几章停一次章节关卡，默认 1。全审间隔=每隔几章做一次全审，默认 5；前 3 章不管间隔都全审。
  • 立项结论（一句话卖点、超越点、差异清单）是这部作品的方向，后面阶段以它为准。节奏以主对标基线为底线，只能比基线更严。

关卡日志规矩

  • 每次拍板追加一行，旧行不动。日期写 YYYY-MM-DD，关卡写「立项、总纲、第 N 卷卷纲、第 N 章」。
  • 决定只写一两句：选了什么、通过还是退回、要改什么。细节留在产物里，这里写去哪看。
  • 理由写作者原话。作者没给就写「作者未说明」，不替作者补。

4总控 /novel

总控是个薄调度器：它不硬编码流程，一切流程知识都委托给上面那张状态机表。每次都先读状态机，再把你要推进的那部作品从当前阶段接续到下一个关卡。

它的五步工作流

  1. 扫描作品库——找三样：作品/*/项目.md（一部作品）、待拍板的 作品/立项方案-*.md、对标库/*/（三份产物齐全算已拆完，只有 原文.txt 算待拆）。
  2. 汇报——每部读书名、平台、「进度」一节、关卡日志最后一行，按状态机查下一步，用固定表格列出。字段缺了或组合不在表里就照实报、不猜。
  3. 接续到下一个关卡——挑要推的那部（你点名的；只有一部能推就它；多部都能推就问你、不替你挑），按 阶段/状态 查表：不在关卡 → 调「下一步」列的 skill 跑完、按「做完改成」改进度、再读一遍，反复循环直到撞上关卡或完结。
  4. 关卡：汇报并等待——停在关卡且你没给决定时，只汇报不越过：一句话点清哪部、哪个关卡、看哪个文件、怎么回复。
  5. 拍板后过关卡——把你的决定落到项目.md，再回第 3 步。总纲/卷纲交 novel-dagang，立项交 novel-lixiang，写章关卡总控自己接。
推进循环（第 3 步的本质）：读进度 → 查状态机「下一步」→ 调那个 skill → skill 按「做完改成」改进度 → 再读进度 → 重复，直到撞上 ★ 关卡或完结。这就是「关卡之外自动往下走」的实现。

5七个 skill 详解

每张卡点击展开。触发 / 输入 / 处理步骤 / 产出 / 上下游 五栏统一格式。

novel-chaishu · 拆书 / 测指标 /novel-chaishu
触发
拆解对标网文源本时用。也可只当「尺子」——只要测机械指标（如审稿基线对比），直接看 METRICS.md、不走拆书全流程。
输入
对标源本 对标库/<书名>/原文.txt；脚本共用词表 套话候选.txt（数套话、找白名单）。
处理步骤
① 测量切章：metrics.py 出 指标.json、split.py 出 章节/ 和 分块.json，精拆范围另测 指标-精拆.json。② 读文案+黄金三章，定题材和情绪点类型库初版。③ 并行分块：每块派一个子代理（任务书 CHUNK-BRIEF.md）。④ 汇总成 语义标注.json，用 semantics.py 算语义指标（不许心算）。⑤ 按 OUTPUTS.md 写三份产物、逐条自检（只讲手法、不复述情节）。
产出
三份正式产物（都在 对标库/<书名>/）：拆书报告.md（含必填的「弱点」，立项找超越点的依据）、基线指标.md、风格档案.md。中间产物：指标.json、指标-精拆.json、章节/、分块.json、语义标注.json（要留着）。
上下游
上游：作者把源本放进 原文.txt。下游：立项读三份找超越点、大纲排节奏、审稿做基线对比、设定读「人设原型」避开对标的形态和人名。
novel-lixiang · 立项 ★关卡 /novel-lixiang
触发
为新作立项（通常指定主对标）；作者对「待拍板的立项方案」做选择/合并时也用（关卡回合）。
输入
基于对标库里已拆完的书（三份产物齐全）。主对标必须已拆完，缺了先请作者 /novel-chaishu。辅助对标最多 2 本、每本写明借鉴项。作者提的要求（平台、篇幅、题材、要/不要的元素）全记进方案。
处理步骤
出恰好 3 个差异化方案（贴近 / 居中 / 最远）。约束：核心装置和主打超越点三方案两两不同；每个超越点必须对上拆书报告「弱点」里的一条具体编号；借功能不借形态；节奏目标只能比基线更严。关卡：贴出三方案+比较表+文件路径，等作者选一个/说清怎么合并/改哪；本轮到此结束、拍板前不建目录。
产出
拍板前：作品/立项方案-<主对标>.md。拍板后建作品：作品/<书名>/项目.md（进度=设定/待开始、关卡日志记本次立项）、风格档案.md（从主对标派生，每条标【继承】/【调整】）、立项方案.md（方案文件改名移入）。
上下游
上游：读 对标库/<主对标>/ 三份产物（尤其「弱点」找超越点、基线定节奏底线）。下游：项目.md 的立项结论成为后续所有阶段的方向真源，设定照拍板方案落地。
关卡分支：选定无改动 → 建作品；要合并/改 → 把最终方案追加到方案文件末尾、再停一次等确认；三个都不要 → 问清楚重出覆盖；「你帮我选」→ 可写「推荐」一节，但要作者明确说选哪个才算拍板。
novel-sheding · 设定 /novel-sheding
触发
给立项完成、进度处于「设定 / 待开始」的作品做设定。没有关卡，做完就推进；要作者拍板的事攒进自检、留到总纲关卡一起看。
输入
模板 规范/模板/设定/ 全部（每次现读）；项目.md 基本信息+立项结论；立项方案.md 的最终方案+主要风险+推荐；风格档案.md；主对标 拆书报告.md 的「人设原型」「核心设定机制」+ 语义标注.json 的「新角色」（要避开的形态和人名）。
处理步骤
① 找作品。② 读材料、把凡写「设定阶段」的地方列成交办清单。③ 选体系：力量体系和关系体系二选一只写一份（变强推进→力量、关系推进→关系）。④ 写设定（结构照模板、立项结论逐项落地、人名不与对标重名同音；真实世界制度/医学/法律用 WebSearch 查实、写「依据」，查不实标【待查】）。⑤ 派一个没参与写的子代理自检（任务书 CHECK.md）。⑥ 改进度「总纲 / 待开始」。
产出
设定/ 下：角色.md、世界观.md、势力.md、力量体系.md 或 关系体系.md、时间线.md；交办另起的文件（如医疗题材的 病例.md）；自检.md（清单 + 交办 + 待作者确认 + 待查）。
上下游
上游：立项产物 + 主对标形态清单。下游：novel-dagang 写总纲时以设定文件为事实底座；模板里的「境界/关系阶梯/主要规则/当前状态」等节名是写章回写、审稿核对的锚点。
novel-dagang · 大纲（总纲/卷纲/章纲/伏笔表）★关卡 /novel-dagang

核心分工：大纲定谁在哪章做什么，设定定事实和规则。

触发
只做进度是「总纲」或「卷纲」的作品。状态「待开始」→ 写；状态「待拍板」且作者本次有决定 → 处理拍板。
输入
项目.md、立项方案.md、设定/ 全部、风格档案.md 的「叙述视角」；主对标 基线指标.md 全文 + 拆书报告的「情绪点类型库/钩子手法/分卷节奏」；规范/模板/大纲/。卷纲阶段加读总纲/伏笔表/自检；第 2 卷起加读全书摘要、上一卷卷摘要、角色当前状态、时间线。
处理步骤
① 定节奏目标（总纲阶段，以主对标基线为底线、立项只能更严）。② 写：总纲切分卷、排关键情节点、登记全书伏笔；卷纲一章一行章纲，写完用 python 从章纲算节奏对照，不达标就改到全过才交关卡。③ 每次交关卡前派子代理做原创性自检（任务书 CHECK.md）。④ 改进度「待拍板」、交作者。⑤ 拍板后：总纲通过 → 接着写第 1 卷卷纲再停；卷纲通过 → 写章 / 待开始。
产出
大纲/总纲.md、大纲/卷纲-NN.md、大纲/伏笔表.md、大纲/自检.md（每次自检追加一节）；可能回写 设定/、建角色卡。
上下游
上游：设定阶段。下游：卷纲通过 → novel-xiezhang 写章。停在总纲、每卷卷纲两类关卡。
原创性自检查五类：① 桥段组合 ② 人物关系结构 ③ 装置的升级路线 ④ 关键节点的场面 ⑤ 信息差怎么清零。判定原则：借功能不算重合，借形态才算；立项结论写死的不算（那是立项关卡过的关）。
novel-xiezhang · 写正文（四模式）/novel-xiezhang

核心原则：章纲定这一章发生什么，设定和前文定什么是真的，风格档案定怎么写。对不上时照设定和前文写、停下报作者。正文文件 作品/<书名>/正文/NNNN-章名.md 只放正文。

模式什么时候做什么
代写进度「写章/待开始」且正文还不在按章纲写当前章（一次一章），字数贴目标 ±15%，自检过 AI 腔清单，写完回写四处，改「写章/待审」。
收稿进度「写章/待开始」且正文已是作者定稿通读作者正文、一个字不改，只测量记录问题、回写四处，改「写章/待审」。
局部代笔作者要写/重写某一段（「这段重写」「补段过渡」）只改指定那段、段外逐字不动，不改进度、不回写（整章成稿后再走收稿）。此条优先。
卷末结算进度「卷末结算/待开始」把本卷卷摘要并入全书摘要，推进到下一卷卷纲；本身不是关卡、不等拍板。
回写四处
代写/收稿写完，只写正文里真发生的：① 角色当前状态（设定/角色.md，档案不动）② 大纲/伏笔表.md（埋了/收了改状态）③ 设定/时间线.md「正文」追加一行 ④ 摘要/卷摘要-NN.md 追加一节。全书摘要只在卷末结算时写。
上下游
上游：卷纲通过（novel-dagang）。下游：每写完一章交 novel-shengao 审稿；卷末结算后交 novel-dagang 写下一卷卷纲。
novel-shengao · 审稿 ★关卡 /novel-shengao
触发
只做进度「写章/待审」的作品（作者点名「全审第 N 章」除外）；审当前章；按「审稿设置」定这次是轻审还是全审。审稿只查、不替作者拍板。
轻审三维
三个子代理并行，只审、只交表、不改任何文件：① 一致性（CONSISTENCY.md，查事实矛盾+抽查回写）② AI 腔（AI-TONE.md，只给正文+清单+风格档案，不给章纲设定，逐条过 A01–A17）③ 字数（WORDCOUNT.md，metrics.py 量，目标 ±15%）。
自动返修
最多 2 轮：三份表都过 → 轻审过；有问题按清单逐条改、复审只重跑受影响的维度；两轮之后仍有问题就停下，写明卡在哪个维度、哪条没修掉。
全审两维
只有全审章走，在轻审收敛、正文不再变后并行加，只测量、不自动返修：① 基线对比（BASELINE.md，metrics.py+semantics.py 对照 基线指标.md）② 读者盲评（READERBLIND.md，只给书名/平台/窗口章号/正文，子代理扮演该平台读者，报弃书点/跳读点/吐槽点+追读意愿分 1–10）。
产出
审稿/NNNN-章名.md，每审一次是一个批次、追加在文件末尾（旧批次不动），标明「轻审 / 全审」。
推进
轻审过 → 按「停顿频率」：到停顿点停「写章/待拍板」等作者拍板，没到则当前章 +1 接着写。两轮没审过 → 一律停「写章/待拍板」交作者。
全审触发公式（N=全审间隔默认 5，M=当前章）：M ≤ 3 → 全审（前 3 章都全审）；M > 3 且 (M−3) 能被 N 整除 → 全审；其余 → 轻审。读者画像只用在读者盲评，平台由项目.md「平台」字段决定（规范/读者画像/<平台>.md）。

规范 / 模板

一份模板对应一个同名产物文件，各作品共用（作者可改）。模板里的节名是写章回写、审稿核对按名字找内容的锚点，改名要连带改用到它的 skill。
