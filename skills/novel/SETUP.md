# 运行准备

七个 skill 共用本文件的运行契约；单独调用任何阶段也先完成准备，不依赖发布仓库根目录的 README 或 AGENTS。

## 两根路径

- **技能目录**：从实际加载的本文件路径定位 `novel` 技能根目录（`SETUP.md` 所在目录），它的父目录就是七个技能的共同父目录，记作 `<技能目录>`。沿已加载文件的路径定位，不从工作区猜 `.claude/skills`、`.agents/skills` 或其他安装位置。文档中的相对链接以该文档所在目录为基准。
- **七件套必须完整同级**：`novel`、`novel-chaishu`、`novel-lixiang`、`novel-sheding`、`novel-dagang`、`novel-xiezhang`、`novel-shengao` 都在 `<技能目录>` 下，各有 `SKILL.md`；引用的脚本、参考文档和默认资产也必须可读。缺项先停止，报告缺失路径，请作者补全安装。
- **工作区**：作者明确指定或确认的写作项目路径，记作 `<工作区>`。路径未明确就先问作者，不把技能安装目录当工作区。确定后把命令的 cwd 设在工作区根并始终维持在那里：`作品/`、`对标库/`、`规范/` 等数据相对路径均从这里解析。

`<技能目录>`、`<工作区>` 和命令中的其他尖括号内容都是文档占位符，不是环境变量。执行前将前两者替换成确认过的绝对路径，将书名、临时目录等替换为实际值，并保留路径外的双引号。脚本用绝对路径调用，不能为找脚本切换 cwd。

## 每阶段开始前

1. **确认两根和七件套**，检查 `python --version` 为 **Python 3.10+**；随附脚本只依赖标准库。缺 Python、版本不符或依赖文件缺失，就停下报告，不继续业务步骤。
2. **幂等补齐工作区**，在工作区根执行：

   ```bash
   python "<技能目录>/novel/scripts/setup.py" "<工作区>"
   ```

   已确认 cwd 就是工作区根时，也支持省略目标参数：

   ```bash
   python "<技能目录>/novel/scripts/setup.py"
   ```

3. **成功才进入业务步骤**。setup 报错或退出码非零就停止，报告原因；目录已经存在不代表准备成功。每个阶段都要确认准备结果，同一轮调度中、同一技能目录与工作区已成功完成的可复用；路径改变、发现文件缺失或新一轮调用时重新检查并运行 setup。

派发子代理时传递两根的绝对路径、相关任务书的实际路径和本轮准备结果，保持其 cwd 在工作区根；这只是运行信息，不扩大任务书允许读取的业务材料。审稿子代理沿用主代理的准备结果，缺失或失败就报回，不自行写入工作区。

## setup 的文件边界

- **资产从技能根找**：相对于 `novel/scripts/setup.py` 所属的 `novel` 根读取 `assets/规范/`，不相对于 cwd，也不依赖安装容器的目录名。缺失或空的必需资产会报错。
- **逐文件补缺，不覆盖**：将默认资产铺到 `<工作区>/规范/`；目标文件已存在就跳过，保留作者的改动。即使 `规范/` 已存在，也要补上其中缺失的默认文件。目标类型冲突等错误必须报出，不能当作成功跳过。
- **仅补工作区基础目录**：`作品/`、`对标库/` 不存在才创建；不会生成作品、修改 `项目.md` 或推进阶段。
- **可反复运行**：已存在文件保持原样，报告新增与跳过数量。更新技能后，新增加的默认文件会补入；已有规范要升级，由作者对照新默认内容决定如何合并，setup 不自动覆盖。
