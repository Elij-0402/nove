# 总控

先扫作品库汇报每部在哪一步，再把作者要推进的那部**从当前阶段接续到下一个关卡**：关卡之外自动往下调度，遇到关卡只汇报、等作者拍板。

**每次都先读 [PROJECT.md](PROJECT.md)。** 项目.md 格式、状态机、停顿频率、关卡日志的规矩都在那里，是唯一真源，下面不重述——每一步「调用谁」「做完改成什么」「哪些是 ★ 关卡」都查它的状态机表。

## 1. 扫描作品库

在工作区根目录找三样：

- **作品**：`作品/*/项目.md`，一个文件是一部作品。`作品/` 下没有项目.md 的目录不归工坊管，只列目录名，不猜进度。
- **待拍板的立项方案**：`作品/立项方案-*.md`（立项关卡停在项目.md 出现之前）。
- **对标库**：`对标库/*/`。`拆书报告.md`、`基线指标.md`、`风格档案.md` 三份都在算已拆完，只有 `原文.txt` 算待拆。

## 2. 汇报

每部作品读项目.md 的书名、平台、「进度」一节、关卡日志最后一行，按状态机表查出下一步。

- **字段缺了，或阶段和状态的组合不在状态机表里，照实报出来**，不猜。
- **按状态机「应有产物」一列核对**，缺了把出入一起报给作者。

```
## 作品
| 作品 | 平台 | 阶段 / 状态 | 卷 / 章 | 下一步 |
|---|---|---|---|---|

## 待拍板的立项方案
文件路径，请作者拍板；没有写「无」。

## 对标库
已拆完：……；待拆：……（`/novel-chaishu`）
```

- **一部作品都没有时**：对标库有已拆完的书，下一步立项（`/novel-lixiang`，指定主对标）；对标库也空，先把源本放进 `对标库/<书名>/原文.txt` 再拆书（`/novel-chaishu`）。

## 3. 接续到下一个关卡

挑要推进的那部：**作者点名的那部**；没点名而只有一部不在关卡也没完结，就那部；**多部都能往下推，汇报完问作者推哪部，不替作者挑**。

对这一部，看项目.md 的 阶段 / 状态，按状态机表办：

- **停在关卡（★），作者这次的话里有对这个关卡的决定**（通过 / 退回 / 要改 / 选某方案 / 合并）→ 先过关（第 5 步），再回本步接着推。
- **停在关卡，没给决定** → 第 4 步汇报、等待。
- **不在关卡** → 调用状态机「下一步」列的那个 skill，让它跑完、按状态机改进度；再读一遍进度，重复本步——直到撞上关卡或完结。
- **skill 没推到预期状态**（报了问题、卡在半路）→ 停下，把它报的问题原样转给作者。

## 4. 关卡：汇报并等待

停在关卡、作者没给决定时，**只汇报，不越过关卡**：

- **一句话点清关卡**：哪部、哪个关卡、看哪个文件（状态机「应有产物」列）、怎么回复（通过 / 退回 / 要改）。
- **立项关卡在项目.md 之前**：`作品/立项方案-*.md`，请作者看方案拍板，决定告诉我或直接调 `/novel-lixiang`。

## 5. 作者拍板后过关卡

把作者的决定落到项目.md，再回第 3 步接着推：

- **总纲 / 卷纲** → 调 `novel-dagang` 处理这次拍板：它记关卡日志、按状态机推进（总纲通过会接着写第 1 卷卷纲、停在卷纲关卡）。
- **立项** → 调 `novel-lixiang` 处理。
- **写章关卡总控自己接**（别的 skill 不管这个关卡）：
  - **通过** → 关卡日志追加一行，按状态机改进度：当前章是本卷最后一章（当前卷 `大纲/卷纲-NN.md` 章纲表的末章）→「卷末结算 / 待开始」，当前章不动；否则当前章 +1、「写章 / 待开始」。
  - **退回 / 要改** → 留在「写章 / 待拍板」，关卡日志记一行（退回、要改什么）。按意见改正文（改一段用 `novel-xiezhang` 局部代笔）；正文改定后进度改回「写章 / 待审」，再回第 3 步——审稿从待审重跑、重新停到关卡。
