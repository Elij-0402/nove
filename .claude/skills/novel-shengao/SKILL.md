# 审稿

给写完的一章做审稿：**轻审每章都做**，**全审按项目.md 的全审间隔另加两维**。

- **轻审**：一致性、AI 腔、字数三个维度由三个子代理**并行**审，每个只拿自己那一份材料。不过就按问题清单**自动返修**，复审，最多 2 轮；仍不过就停下交作者。
- **全审**：在轻审之上，等正文定下来（返修收敛）后，再**并行**加两维——基线对比、读者盲评，都只测量、不自动返修，结论进报告交作者判断。细则见第 6 步。

每审一次产出一份批次报告，存进 `作品/<书名>/审稿/`，再把进度从「写章 / 待审」推进到章节关卡。

**审稿只查，不替作者拍板。** 待拍板是关卡，作者看正文和审稿报告定通过还是退回。

## 1. 找作品，定这次是轻审还是全审

- **只做进度是「写章 / 待审」的作品**（作者点名要「全审第 N 章」这类的除外，见下）。作者点了名就用那一部，进度对不上就停下报给作者。没点名，找 `作品/*/项目.md` 里处在这个进度的；有好几部就问作者。
- **审的是项目.md「当前章」那一章**，正文文件是 `作品/<书名>/正文/NNNN-章名.md`。文件不在就停下报给作者。
- **按项目.md「审稿设置」定这次做轻审还是全审**（字段含义以 [PROJECT.md](../novel/PROJECT.md)「审稿设置」为准）。读「全审间隔」的数字（记作 N，默认 5）和「当前章」（记作 M）：
  - **前 3 章每章都全审**：M ≤ 3 → 全审。
  - **之后每隔 N 章一次**：M > 3 且 (M − 3) 能被 N 整除 → 全审。
  - **其余 → 轻审。**
  - 举例：N=5 时全审落在第 1、2、3、8、13、18… 章；作者把 N 改成 3，就变成第 1、2、3、6、9、12… 章；改成 1 就每章都全审。间隔改了，触发时机随之变。
- **作者直接点名「全审第 N 章」**：就对那一章做全审，不看间隔；那一章的正文文件不在就停下报给作者。

## 2. 派三个子代理并行轻审

**这一步主代理自己不读正文和设定，只读项目.md 的进度、当前章、每章目标字数，定位正文文件。** 三个维度各派一个子代理，在同一条消息里一起发，并行跑。每个子代理的任务书是对应文件的全文，后面附上书名、当前章的章号和正文文件路径：

- **一致性** → [CONSISTENCY.md](CONSISTENCY.md)。给它正文、章纲、设定、伏笔表、角色卡、时间线、卷摘要、前文；查事实矛盾，抽查回写对不对。
- **AI 腔** → [AI-TONE.md](AI-TONE.md)。只给它正文、`规范/AI腔清单.md`、这部作品的风格档案；**不给章纲和设定**，免得它顺着剧情把 AI 腔读顺了。
- **字数** → [WORDCOUNT.md](WORDCOUNT.md)。只给它项目.md 的每章目标字数和正文文件；用脚本量。

- **每个子代理只审、只交表，不改任何文件。** 三份表交回主代理，主代理来返修。
- **材料各拿各的**：一致性要通读设定和大纲，AI 腔和字数拿到的越干净越好，别把设定塞给它们。

## 3. 汇总判定

- **三份表都「通过」→ 轻审过了**，跳到第 6 步（全审章）或第 7 步（轻审章）。
- **有一份查出问题 → 不通过**，进第 4 步返修。
- **三份表原样收好**：报告里照实列，返修照它改。

## 4. 自动返修

**按问题清单一条一条改，只改被点到的地方，不顺手改别处。** 返修要动正文时，主代理这时才读正文。

- **字数**：超了删场面里最不吃紧的铺陈和动作；不够补动作和对白，不注水、不加总结。口径和写章一致（`metrics.py` 的字数，±15%）。
- **AI 腔**：照清单那一条的「改法」改——先删，删了场面还立得住就不补；立不住才用改法里的写法补。白名单里的词超了上限，减到上限以内。
- **一致性**：看子代理判的「该改哪里」——
  - **正文写错了事实**（和设定、前文、伏笔对不上）→ 改正文，以设定和前文为准。
  - **回写错了**（角色当前状态、伏笔表、时间线、卷摘要和正文对不上，或漏回写、状态没改对）→ 改那个回写文件，以正文为准。
  - **设定自身矛盾，或要改的是上游大纲、立项**（比如立项和时间线对不上、章纲和病例对不上）→ **审稿不自行拍板**，正文照原样留着，挂「待作者对齐」写进报告，交待拍板关卡由作者定。
- **返修动了正文里已经回写的事实，一并更新对应的回写文件。**

## 5. 复审与轮次

- **返修完复审：重跑被返修影响的维度。** 改了正文（删套话、增删字数、改事实）→ 字数、AI 腔、一致性都可能变，三个都重跑；只改了回写文件（角色状态、伏笔表、时间线、卷摘要）→ 只重跑一致性。没被影响的维度沿用上一轮结论。复审交回原来那个维度的子代理，它已经读过材料。
- **最多返修 2 轮。** 首审不过返修一轮、复审；还不过再返修一轮、复审；两轮之后仍有问题，**停下，不再返修**。
- **停下时说明卡在哪**：哪个维度、哪条问题两轮没修掉、为什么修不动（比如删字数就犯 AI 腔、改 AI 腔就掉字数，两头够不着），写进报告，交作者定夺。

## 6. 全审：正文定下来后再并行加两维

**只有全审章走这一步；轻审章跳到第 7 步。** 等第 3–5 步的轻审收敛（通过，或两轮没过已停手）、**正文不再变**之后再做，好让这两维量的是作者将看到的最终文本。两维各派一个子代理，在同一条消息里一起发，并行跑；任务书是对应文件的全文，后面附上主代理该给的信息：

- **基线对比** → [BASELINE.md](BASELINE.md)。附书名、主对标名、窗口章号范围和各章正文文件路径、每章目标字数。窗口取**第 1 章到当前章的成稿正文**（新作前期章少，累计就是最近）。它用脚本量机械指标、读正文标语义指标，和 `对标库/<主对标>/基线指标.md` 并排。
- **读者盲评** → [READERBLIND.md](READERBLIND.md)。**只附书名、平台、窗口章号范围和正文文件路径，别的一律不给。** 平台取项目.md 基本信息的「平台」，对应 `规范/读者画像/<平台>.md`。它只拿正文和读者画像，报弃书点、跳读点、吐槽点和追读意愿分。

- **这两维只测量、不自动返修。** 偏离基线、追读意愿低、弃书点，都写进报告交作者在关卡上判断，主代理不据此改正文（除非某条正好命中轻审维度，才并进第 4 步的返修）。
- **盲评子代理交回的「收到的材料」照抄进报告**，证明它没拿到设定和大纲。

## 7. 写批次报告

按 [OUTPUTS.md](OUTPUTS.md) 写 `作品/<书名>/审稿/NNNN-章名.md`：轻审章写三部分（问题、返修记录、本批状态），全审章在返修记录之后多写一节「全审两维」（基线对比、读者盲评）。每审一次是一个批次，同一章再审就在文件末尾追加一个新批次，旧批次不动；批次标题标明是轻审还是全审。

## 8. 推进与停下

先改项目.md 的进度，当前卷不变：

- **轻审过了** → 按 [PROJECT.md](../novel/PROJECT.md) 状态机和项目.md「审稿设置」的停顿频率推进：到停顿点（默认停顿频率 1 时每章都是，本卷最后一章总是）停在「写章 / 待拍板」等作者拍板；没到停顿点就当前章 +1、改「写章 / 待开始」接着写。细则以 PROJECT.md 为准。
- **全审章的两维不改推进**：停不停仍照上面停顿频率走，全审不自行覆盖。全审两维查出的发现（弃书点、追读意愿、基线偏离）只写进报告和给作者的回复；有值得作者定夺的发现就在回复里重点标出、提醒作者过目。
- **两轮没审过** → 一律改「写章 / 待拍板」，当前章不变，不管停顿频率都停下交作者。
- **备注**：轻审过了写「审稿通过」或「审稿 N 轮返修后通过」；全审章补一句全审结论（追读意愿分、偏离与否、有没有弃书点）；有待作者对齐的项一并点一句；没审过写「审稿 2 轮未过，卡在 X，待作者拍板」。

然后回复作者：

- **审稿结论**：这次是轻审还是全审；一次过、返修几轮后过、还是两轮没过卡在哪。
- **三个维度各查出什么、改了什么**，一维一两句；全审章再加基线对比和读者盲评各一两句（追读意愿分、主要偏离、弃书/吐槽点）。
- **本批动过的文件**：正文改了哪几段、哪些回写文件；都没动写「无」。
- **报告文件路径。**
- **下一步**：停在待拍板的，作者看正文和报告拍板（通过就当前章 +1 接着写下一章，本卷最后一章则进卷末结算；退回就按意见改完再拍）；直接进了下一章的，下一步是写章（`/novel-xiezhang`）。
